# Sales Intelligence — End-to-End Machine Learning

A simple company-oriented Sales ML project covering:

- Data validation and cleaning
- Exploratory/business analytics
- Profitability classification
- Model evaluation
- Streamlit deployment UI
- Lightweight local RAG
- Simple agent/tool routing
- Basic upload security
- Application monitoring/logging

## 1. Project idea

The system helps a sales/business team answer:

- How much did we sell?
- How much profit did we make?
- What is the profit margin?
- How many transactions were loss-making?
- Which categories are most/least profitable?
- Which regions are most/least profitable?
- How does discount relate to profit?
- Is a new sales transaction likely to be profitable?

The ML target is:

`Profitable = 1 if Profit > 0 else 0`

## 2. Dataset

The included demo dataset contains 10,194 retail sales records and 21 columns.

The system does not assume the uploaded data is perfectly clean. It:

1. Removes exact duplicate rows.
2. Converts dates.
3. Converts key numeric columns.
4. Removes rows missing required ML/business fields.
5. Creates `Ship Days`, `Order Month`, `Order Year`.
6. Creates the target `Profitable`.

For the supplied demo data, no missing values or exact duplicates were found before processing.

## 3. Model

The project uses a simple Random Forest classifier with:

- train/test split: 80/20
- stratification
- one-hot encoding for categorical features
- median/mode imputation
- class balancing
- fixed random seed

Metrics shown in the application:

- Accuracy
- Precision
- Recall
- F1
- ROC-AUC
- Confusion Matrix

Important: CV numbers must be taken from the actual run on the final dataset. Do not copy demo numbers blindly.

## 4. RAG and Agent

The project intentionally keeps the AI layer simple.

### RAG

`src/rag.py` builds a small local knowledge base from the uploaded dataset, then uses TF-IDF retrieval to find relevant business facts.

No external LLM is required.

### Agent

`src/agent.py` is a simple router:

- Profit questions → business summary
- Category/product questions → category analysis
- Region questions → regional analysis
- Other questions → local RAG retrieval

This is intentionally simple and easy to explain in an interview.

## 5. Security

The upload layer:

- Allows only CSV/XLSX
- Limits files to 10 MB
- Validates required columns
- Never executes uploaded files
- Does not require sending company data to an external AI API

For real enterprise data, deploy inside private company infrastructure/VPC.

## 6. Monitoring

`src/monitoring.py` records:

- pipeline completion
- pipeline errors
- prediction events
- assistant questions/tools
- processing time

Logs are written to `logs/app.log`.

## 7. Run locally on Windows

Open PowerShell inside the project folder.

### Create environment

```powershell
python -m venv .venv
```

### Activate

```powershell
.venv\Scripts\activate
```

### Install packages

```powershell
pip install -r requirements.txt
```

### Run

```powershell
streamlit run app.py
```

The browser should open the Streamlit application.

## 8. How a company would use it

The user opens the deployed Streamlit URL.

Then:

1. Click `Upload your sales data`.
2. Upload the company's CSV/XLSX.
3. The system validates the file.
4. Data is cleaned.
5. Business KPIs are calculated.
6. The ML model is trained on the uploaded dataset.
7. Accuracy/Precision/Recall/F1/ROC-AUC are displayed.
8. The dashboard shows sales/profit insights.
9. The user can ask questions through the local assistant.
10. A new transaction can be tested for profitability.

## 9. Deployment

The simplest deployment is a Streamlit-compatible hosting service.

For a real company, use private infrastructure or a private cloud deployment because sales/customer data can be confidential.

Do not put company data into GitHub.
